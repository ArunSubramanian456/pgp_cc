Fargate networking

The standard layout, and what to check when something can't connect.

Standard layout

Internet → internet gateway → ALB (public subnets, ≥2 AZs, sg-alb: 443 from 0.0.0.0/0)
        → ip target group → tasks (private subnets, 2 AZs, sg-tasks: 8000 from sg-alb, no public IP)
Tasks → out via NAT gateway (any internet) or VPC endpoints (AWS services only)

Two questions for every app

What may come in? APIs: an ALB. Batch, workers, planners: nothing.

How does it get out? Every task needs a way out, at the very least to pull its image. docs

Load balancer rules

  • An ALB needs subnets in ≥2 different AZs. docs
  • Target type must be ip for awsvpc/Fargate. docs
  • ECS registers and deregisters task IPs automatically.
  • containerPort must match portMappings.
  • Set healthCheckGracePeriodSeconds longer than your model's load time.

Endpoints a Fargate task (platform 1.4.0+) needs to pull from ECR privately: ecr.dkr, ecr.api, S3 gateway (image layers live in S3), plus logs (awslogs) and secretsmanager or ssm if you use secrets. re:Post · ECR docs

Agents calling Bedrock from a private subnet need a NAT gateway or a Bedrock endpoint for the same reason.

Port consistency

Every app port (e.g. Uvicorn's default 8000) must match in five places: the app's --port, portMappings.containerPort, the service's loadBalancers.containerPort, the target group port and health check, and the task SG inbound rule. Bind the app to 0.0.0.0, not 127.0.0.1. Customers use 443 on the ALB. Uvicorn docs

Config locations

Task definition: networkMode: awsvpc, portMappings.

Service or RunTask: networkConfiguration.awsvpcConfiguration (subnets, securityGroups, assignPublicIp).

Service only: loadBalancers (targetGroupArn, containerName, containerPort), healthCheckGracePeriodSeconds.

Service-to-service: Service Connect

Call another ECS service by name (http://assistant-api:8000). ECS adds a proxy to each task that finds healthy tasks, spreads requests and reports metrics. AWS's recommended option for ECS-to-ECS calls; an internal ALB is the alternative. Task definition: name the port ("name": "api"). Server service: serviceConnectConfiguration with services[].portName + clientAliases. Client service: {"enabled": true, "namespace": "…"}. Security groups still decide who may connect. Applies on deployment. docs
