Scaling an ECS service

Target tracking, queue workers, scale-in protection.

What it changes

Service Auto Scaling moves desiredCount between min and max (the scalable target, dimension ecs:service:DesiredCount). The service then starts or stops tasks. docs

aws application-autoscaling register-scalable-target --service-namespace ecs \
  --scalable-dimension ecs:service:DesiredCount \
  --resource-id service/CLUSTER/SERVICE --min-capacity 2 --max-capacity 10

Attaches to a service only (not task definitions, clusters or standalone tasks), as a separate step after the service exists. Once on, it owns desiredCount.

Policy types

TypeUse for
Target trackingDefault. "Keep metric near X." Manages its own alarms (don't edit them).
Step scalingFull control over step sizes and reaction speed. You create the alarms.
ScheduledKnown peaks (e.g. raise min at 07:00 on Mondays).

Picking the metric

AppMetric
CPU-bound API (inference, LP solves)ECSServiceAverageCPUUtilization
I/O-bound API (waits on LLMs, databases)ALBRequestCountPerTarget (not supported with the blue/green deployment type)
Memory-boundECSServiceAverageMemoryUtilization
Queue workerBacklog per task (metric math), never raw queue depth or CPU

Ask: which number actually rises when this app is busy? Leave headroom in the target (e.g. CPU 60%) to cover the startup time of new tasks.

Arithmetic

new desiredCount  ≈ current tasks × (current metric ÷ target)
backlog per task  = ApproximateNumberOfMessagesVisible ÷ RunningTaskCount
target value      = acceptable wait ÷ seconds per message      (600 s ÷ 30 s = 20)

RunningTaskCount needs Container Insights on the cluster. No data → no scaling. Keep min ≥ 1 for backlog-per-task. Max capacity must fit the Fargate vCPU quota. docs

Target tracking rules

  • Out fast and in proportion; in gradually. Rounds cautiously.
  • Insufficient data → no scaling (never treated as low).
  • Several policies: out if any wants to, in only if all agree.
  • Scale-in is off during deployments; scale-out continues.
  • Cooldowns: short for out (e.g. 60 s), longer for in (e.g. 300 s).

Task scale-in protection

PUT $ECS_AGENT_URI/task-protection/v1/state  {"ProtectionEnabled": true, "ExpiresInMinutes": 15}
PUT $ECS_AGENT_URI/task-protection/v1/state  {"ProtectionEnabled": false}
GET $ECS_AGENT_URI/task-protection/v1/state
  • ExpiresInMinutes: 1 to 2,880. Default 120, then protection switches off.
  • Service tasks only (standalone tasks get TASK_NOT_VALID).
  • Blocks scale-in and deployments only, not Spot interruptions or crashes.
  • From outside the task: the UpdateTaskProtection API.
