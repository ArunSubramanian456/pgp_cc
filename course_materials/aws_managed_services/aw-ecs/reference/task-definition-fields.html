The two roles

Execution role

Used by ECS/Fargate to start your task:

  • pull from private ECR
  • send logs to CloudWatch
  • fetch secrets

Your containers can't use its credentials. Managed policy: AmazonECSTaskExecutionRolePolicy. docs

Task role

Used by your code once it's running, for things like S3 reads and writes, Bedrock, DynamoDB or SQS. Give each app its own role with only the permissions it needs.

Rule: if it fails before your code runs, check the execution role. If your code gets AccessDenied, check the task role.

Network modes

ModeMeaningFargate?
awsvpcTask gets its own network interface, IP and security groupsRequired
bridgeShares the host interface through a Docker bridge. Default if unsetNo (EC2)
hostDirectly on the host networkNo (EC2, Managed Instances)
noneNo external networkingNo (EC2)

The task definition says how (awsvpc). RunTask or the service's networkConfiguration says where: subnets in one VPC, security groups, assignPublicIp. Use your own private subnets, with a NAT gateway or VPC endpoints so the task can reach ECR, S3 and CloudWatch. docs

Run-time overrides

  • Order of priority: RunTask override > task definition environment > Dockerfile ENV. command in the task definition replaces the image's CMD, and an override replaces both.
  • All overrides together are limited to 8,192 characters, so pass an S3 pointer, not the data. startedBy (up to 128 characters) tags a batch. docs
  • For scenarios, use one pinned revision and many runs, never many revisions.

Stop lifecycle

(behind a load balancer: deregister first) → SIGTERM → wait up to stopTimeout (30s default, 120s max) → SIGKILL

It happens on: StopTask, deployments, scale-in, Fargate Spot interruptions (2-minute notice), and when an essential container stops.

It doesn't happen when the process exits on its own. Long solves should checkpoint on SIGTERM. AWS blog

One blueprint, many runs

When you run a task, you can override a container's command and environment variables for that run only. This is how Scenario Lab runs 200 what-ifs from a single revision. docs
