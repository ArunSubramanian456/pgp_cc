How ECS resolves a tag

  • Services: once per deployment. First task's digest is recorded and reused for all later tasks, scale-outs included ("software version consistency"). A moved tag is picked up only by a new deployment (Force new deployment). Per container: "versionConsistency": "enabled"|"disabled". docs
  • Standalone tasks (RunTask): resolved at every start. A movable tag = same revision, different code.

Tag immutability

aws ecr create-repository --repository-name NAME --image-tag-mutability IMMUTABLE
aws ecr put-image-tag-mutability --repository-name NAME \
  --image-tag-mutability IMMUTABLE_WITH_EXCLUSION \
  --image-tag-mutability-exclusion-filters filterType=WILDCARD,filter=dev-*

Values: MUTABLE (default), IMMUTABLE, MUTABLE_WITH_EXCLUSION, IMMUTABLE_WITH_EXCLUSION. Pushing an existing immutable tag → ImageTagAlreadyExistsException. Habit: unique tag per build (date + git commit). docs

Trap: mutable tag moves → pinned image becomes untagged → "expire untagged" deletes it → scale-out/replacement tasks fail with CannotPullContainerError … @sha256:… not found. Avoid with immutable unique tags; protect baselines with a tag no rule matches (e.g. baseline-*). docs

CVE = Common Vulnerabilities and Exposures: one public ID per known flaw (CVE-2024-3094 = year + number). Severity (CRITICAL…LOW, CVSS 0-10) is separate. A finding = CVE + severity + package + version (+ fixed version). Fix = rebuild with the patched package, deploy the new tag.

Findings are a report: nothing in ECS blocks a pull because of them. docs

Secrets in a container definition

"secrets": [
  { "name": "API_KEY",     "valueFrom": "arn:aws:secretsmanager:REGION:ACCT:secret:NAME-AbCdEf" },
  { "name": "DB_PASSWORD", "valueFrom": "arn:…:secret:NAME-AbCdEf:password::" },
  { "name": "DB_HOST",     "valueFrom": "arn:aws:ssm:REGION:ACCT:parameter/app/db-host" } ]

Full form: …:secret:NAME:json-key:version-stage:version-id; keep the colons when parts are empty. Default version = AWSCURRENT. JSON key/version needs Fargate platform 1.4.0+. docs

  • Execution role fetches: secretsmanager:GetSecretValue, ssm:GetParameters, kms:Decrypt (customer managed key only). docs
  • Injected at container start only. After rotation: Force new deployment (services) or new task. Frequent rotation → read at runtime via SDK with the task role.
  • Failure → ResourceInitializationError: unable to pull secrets or registry auth, before your code runs. Check execution role, ARN, network path. re:Post
  • Visible to the app, logs and debug tools as env vars. Never log the environment; never bake keys into images.
  • AWS APIs (Bedrock, S3, SQS): no secret needed, the task role supplies temporary credentials.
