When to use Managed Instances · ECS cluster capacity

Decision order

GPU / >32 vCPU / >244 GB / privileged / specific type?  → Managed Instances (EC2 type for full control)
otherwise                                              → Fargate
interruptible + retry-safe?                            → Fargate Spot (with a FARGATE base)
native libs all have ARM builds?                       → ARM64 (~20% off)
HTTP service receiving traffic?                        → Express Mode to set it up
steady 1-3 yr usage?                                   → Compute Savings Plan (up to 50% off)

Settings

"runtimePlatform": { "operatingSystemFamily": "LINUX", "cpuArchitecture": "ARM64" }

"capacityProviderStrategy": [
  { "capacityProvider": "FARGATE",      "base": 2, "weight": 1 },
  { "capacityProvider": "FARGATE_SPOT", "weight": 3 } ]

Images and architecture: distro comes from the base image (host shares only the kernel); CPU architecture is baked in (build machine's by default). amd64 image on ARM64 task → exec format error, "Essential container in task exited", exit 1. No runtimePlatform → x86. Multi-arch: docker buildx build --platform linux/amd64,linux/arm64 -t REPO:TAG --push . (image index; each task pulls its match). Inspect: docker buildx imagetools inspect REPO:TAG. re:Post

base = first N tasks on that provider; weight = split of the rest (here 1 : 3).

Express Mode

Inputs: image, task execution role, infrastructure role. Creates on Fargate: task definition, service (canary deployments), ALB with HTTPS + ACM cert, security groups, target tracking auto scaling, log group, deployment alarms. Ordinary, editable resources; ≤ 25 services can share one ALB. For web services only, not jobs or queue workers. docs
