Infrastructure as code: a first look

Your capstone's sandbox, written as about 50 lines of Python

Your win for this lesson (about 25 minutes) You can read a CDK stack and point to which line carries which design decision from your capstone: subnets, security group, task definition, image, roles. You'll also know what CDK writes for you, and what you still have to decide yourself.

1 · What infrastructure as code is, and what CDK adds

So far you've designed everything on paper. Built by clicking in the console, it would be dozens of screens, hard to repeat and impossible to review. Infrastructure as code writes the same resources as a file you can read, review, version in git, and create or delete with one command.

AWS CDK lets you write that file in Python. It doesn't create anything itself: it turns your Python into a CloudFormation template, and CloudFormation creates the resources.[1]

your Python stack ──cdk synth──▶ CloudFormation template ──cdk deploy──▶ VPC, ECR, task definition, roles…
                                (JSON, often 10× longer)                  cdk destroy removes them all

CDK's building blocks are constructs. Most of what you'll use are ones with sensible defaults and helper methods: ecs.FargateTaskDefinition, ec2.Vpc, ecr.Repository. Their grant… methods write IAM policies for you, scoped to exactly the resources involved.[2] That matters, because roles were the hardest part of your capstone.

You don't need an AWS account to read or even write CDK. You only need one to deploy it.

2 · The sandbox, as code

This is the piece of your design that uses Parts 1, 2, 3 and 6 at once. Before you click each highlighted block, say which part of your design it is, and what it's protecting against.

from aws_cdk import Stack, Duration
from aws_cdk import aws_ec2 as ec2, aws_ecs as ecs, aws_ecr as ecr, aws_s3 as s3, aws_logs as logs

S3_PREFIX_LIST_ID = "pl-…"   # S3's address list for eu-west-2 (aws ec2 describe-managed-prefix-lists)

class SandboxStack(Stack):
    def __init__(self, scope, id, **kwargs):
        super().__init__(scope, id, **kwargs)

        vpc = ec2.Vpc(self, "Vpc", max_azs=2, nat_gateways=1,
            subnet_configuration=[
                ec2.SubnetConfiguration(name="public",  subnet_type=ec2.SubnetType.PUBLIC),
                ec2.SubnetConfiguration(name="app",     subnet_type=ec2.SubnetType.PRIVATE_WITH_EGRESS),
                ec2.SubnetConfiguration(name="sandbox", subnet_type=ec2.SubnetType.PRIVATE_ISOLATED),
                ec2.SubnetConfiguration(name="data",    subnet_type=ec2.SubnetType.PRIVATE_ISOLATED),
            ])
        vpc.add_gateway_endpoint("S3", service=ec2.GatewayVpcEndpointAwsService.S3)
        for name, svc in [("EcrApi",    ec2.InterfaceVpcEndpointAwsService.ECR),
                          ("EcrDocker", ec2.InterfaceVpcEndpointAwsService.ECR_DOCKER),
                          ("Logs",      ec2.InterfaceVpcEndpointAwsService.CLOUDWATCH_LOGS)]:
            vpc.add_interface_endpoint(name, service=svc)

        repo = ecr.Repository(self, "SandboxRepo",
            image_tag_mutability=ecr.TagMutability.IMMUTABLE,
            lifecycle_rules=[
                ecr.LifecycleRule(rule_priority=1, tag_status=ecr.TagStatus.UNTAGGED,
                                  max_image_age=Duration.days(7)),
                ecr.LifecycleRule(rule_priority=2, tag_status=ecr.TagStatus.TAGGED,
                                  tag_pattern_list=["20*"], max_image_count=20),
            ])

        bucket = s3.Bucket(self, "Artifacts", enforce_ssl=True,
                           block_public_access=s3.BlockPublicAccess.BLOCK_ALL)

        sandbox_td = ecs.FargateTaskDefinition(self, "SandboxTask",
            cpu=1024, memory_limit_mib=2048,
            runtime_platform=ecs.RuntimePlatform(
                operating_system_family=ecs.OperatingSystemFamily.LINUX,
                cpu_architecture=ecs.CpuArchitecture.ARM64))
        sandbox_td.add_container("sandbox",
            image=ecs.ContainerImage.from_ecr_repository(repo, tag="2026-10-24-a1b2c3d"),
            logging=ecs.LogDrivers.aws_logs(stream_prefix="sandbox",
                                            log_retention=logs.RetentionDays.ONE_MONTH),
            stop_timeout=Duration.seconds(30))

        bucket.grants.read(sandbox_td.task_role, "runs/*")
        bucket.grants.put(sandbox_td.task_role, "runs/*")

        sandbox_sg = ec2.SecurityGroup(self, "SandboxSg", vpc=vpc, allow_all_outbound=False)
        sandbox_sg.add_egress_rule(ec2.Peer.ipv4(vpc.vpc_cidr_block), ec2.Port.tcp(443),
                                   "interface endpoints")
        sandbox_sg.add_egress_rule(ec2.Peer.prefix_list(S3_PREFIX_LIST_ID), ec2.Port.tcp(443),
                                   "S3 gateway endpoint")

        # in the API's stack:  sandbox_td.grant_run(api_task_definition.task_role)
Part 2, subnets. Four tiers in 2 AZs. PRIVATE_WITH_EGRESS gets a route to the NAT gateway (the API's way to the search and weather APIs). PRIVATE_ISOLATED subnets have no route to or from the internet, which is exactly what the sandbox and the database need.[3] nat_gateways=1 is the Part 8 budget decision: one NAT, not one per AZ, and you made that choice on purpose.
Part 2, ways out. The free S3 gateway endpoint, plus the three interface endpoints the sandbox can't start without: ECR API, ECR Docker and Logs. The API would add SECRETS_MANAGER and Bedrock runtime the same way. Each interface endpoint is one line here, and an hourly charge per AZ on the bill.
Part 6, images. Immutable tags, so a tag always means the same image. Two lifecycle rules: expire untagged images after 7 days, and keep the newest 20 builds. Notice what isn't here: a rule expiring tagged images by age, the trap from your first Part 6 answer.
Parts 1 and 8, the blueprint. 1 vCPU and 2 GB, as the brief says, on ARM64 for about 20% less. Remember lesson 10's catch: the image must then be built for arm64. Note what's missing: no subnets, no security group. A task definition never holds them (your ALB question).
Parts 6 and 7, the container. from_ecr_repository(repo, tag=…) pins one immutable tag, and also lets CDK grant the execution role permission to pull from this repository. aws_logs sets up awslogs with a one-month retention, and grants the execution role permission to write those logs. So the execution role's whole policy is written for you, which is the role you put "logs" on the wrong side of in Part 3. stop_timeout is lesson 2's SIGTERM-to-SIGKILL gap.
Part 3, the sandbox's task role. Read and write runs/* only. CDK writes the policy, scoped to that prefix.[4] No Bedrock, no secrets, no database: those simply aren't granted, and nothing is allowed unless granted. (Older CDK versions write bucket.grant_read(role, "runs/*").)
Part 2, the sandbox's guard. allow_all_outbound=False is the line that matters: without it, the group allows everything out, the default you asked about. Then two narrow exits: 443 inside the VPC (the interface endpoints) and 443 to S3's address list. No inbound rules at all. S3_PREFIX_LIST_ID is S3's published address list for the Region; you look it up once.
Part 3, PassRole, in one line. grant_run gives the API's task role ecs:RunTask on this task definition and iam:PassRole for exactly its roles.[5] The JSON you wrote by hand in the capstone, generated and scoped for you.
Where do the sandbox's subnets and security group go, then? Into the API's RunTask call, at run time: networkConfiguration with the sandbox subnet IDs, sandbox_sg, and assignPublicIp: DISABLED. The stack passes those IDs to the API as plain environment variables. It's the same split as your ALB question: the blueprint doesn't say where; whoever starts the task does.

3 · What CDK writes for you, and what it doesn't

CDK writes it for youStill your decision
Route tables, NAT routing, endpoint DNS settingsWhich subnet tier each piece lives in
The execution role and its ECR-pull and log-write policyWhich repository, which tag, how long logs are kept
Scoped IAM policies from grant… calls, including PassRoleWhat to grant at all (the sandbox gets almost nothing)
The ECR lifecycle policy JSONRules that can't delete a running image
Security group resourcesTurning off "allow all outbound" for untrusted code

Naming note: Python CDK writes memory_limit_mib; the online API reference sometimes shows it as memory_limit_mi_b. The code is a teaching sketch: cdk synth is the real check once you install CDK.

CDK makes the right design shorter to write. It doesn't choose the design. Every highlighted line above is a decision you made in the capstone.

Practice: spot the problem

When you get an account

cdk bootstrap     once per account and Region: sets up what CDK needs to deploy
cdk synth         print the CloudFormation template (works without deploying)
cdk diff          what would change, before you change it
cdk deploy        create or update the resources
cdk destroy       delete them, so an experiment costs only the hours it ran

Habit worth forming: always run cdk diff before cdk deploy, and read it like a code review. It's lesson 6's "know what a deployment will do" applied to infrastructure.
